# Калькулятор и форма заявки (`/calculator`) — как устроено

Описание страницы калькулятора (ID 709) и формы заявки на ней: разбор файлов проекта, расчёт,
связь с формой, черновиком и панелью. Источник истины — код в ветке `ivan_claude`; этот файл
объясняет, *почему* код такой и *как* части связаны. Приём заявок, CRM и серверная формула —
в [README панели](../../../plugins/pcb-panel/README.md).

**Правило обновления.** Любой чат, который меняет `calculator.js`, `calculator.css`, разметку
`709-calculator.html` или то, как калькулятор передаёт данные форме, в том же коммите правит этот
файл: карту файлов, затронутый раздел и журнал решений в конце. Перед работой с калькулятором
файл читается первым.

Статусы разделов: ✅ работает в коде · 🔧 решено, ещё не реализовано · ❓ открытый вопрос.

## 2. Страница ✅

- **Шапка** `.cx-head`: «Онлайн-калькулятор» + надстрочное «beta» (`.cx-head__beta`, золотой) и короткий подзаголовок `.cx-head__sub`.
- **Этап 1 «Файлы проекта»** `#calc-files`: зона загрузки `#calc-drop` (файлы, папки, архивы; фильтра
  `accept` нет — у Gerber любые расширения), список файлов, блок плат `#calc-boards` (если плат несколько),
  отчёт «Что взято из файлов» `#calc-report` (раскрыт при первой загрузке; видны только строки, требующие
  внимания, остальные — под «Ещё N значений взяты из файлов — показать»), четыре спойлера: какие файлы
  подойдут (по категориям), как выгрузить из САПР (KiCad, Altium, OrCAD/Allegro, EasyEDA Pro — с отметкой
  Beta), куда попадают файлы, демо-проект.
- **Этап 2 «Параметры платы»**: тираж (в комплекте — «Комплектов, шт»), габариты, слои, толщина, медь,
  материал, покрытие, цвета; «Ещё параметры» `#calc-more` — дорожка, отверстие, расположение компонентов,
  поставка, особые требования (импеданс, слепые отверстия, via-in-pad, ламели).
- **Этап 3 «Компоненты и монтаж»**: без монтажа / быстрая оценка / подробная (таблица групп корпусов).
  Компоненты закупаем сами (заказчик их не поставляет), их стоимость в оценку не входит — «по BOM».
- **Итог** `#calc-summary` — липкая панель справа (на телефоне — свёрнутая полоса снизу): вилка, цена за
  плату или за комплект, строки «из чего складывается», срок, «Отправить на точный расчёт».
- **Этап 4** — форма заявки (§8).

## 3. Разбор файлов ✅

Всё разбирается **в браузере**; файлы на сервер не уходят, пока клиент сам не приложит их к заявке.

### 3.1 Что принимаем

| Источник | Как распознаём | Что даёт |
|---|---|---|
| IPC-2581 (`.xml`, `.cvg`) | `<IPC-2581` в начале файла | Почти всё: стек, медь, материал, цвета, покрытие, контур, отверстия, дорожка, компоненты с выводами и сторонами, BOM |
| ODB++ (`.tgz`, `.tar`, `.zip`, папка `odb/`) | `matrix/matrix` в архиве | Слои, медь (`.copper_weight`), контур (`profile`), дорожка (символы `rNNN` у линий), отверстия (`tools`), компоненты (`eda/data` + `comp_+_top/bot`) |
| Файл требований (`.txt`, `.md`) | ≥ 3 строк «Ключ: значение», RU/EN | Тираж, слои, толщина, медь (oz/мкм), материал, покрытие, цвета, отверстие, дорожка, габариты |
| `.gbrjob` | расширение | Размер, слои, толщина, медь, покрытие, цвета, материал, дорожка |
| Pick&Place: Altium `.csv`/`.txt`, KiCad `.pos`/`.csv` | заголовок с Designator/Ref, X, Layer/Side | Число компонентов и стороны — точно; SMD/DIP и выводы — по посадочным местам (оценка) |
| Gerber и сверловка | `%TF.FileFunction` (X2), иначе расширения (`.GTL`, `.GM*`, `.GKO`, `F_Cu`…), сверловка — `M48` | Габариты по контуру, слои, мин. апертура как оценка дорожки, отверстия, SMD-площадки на пасте |

- **Архивы:** ZIP (JSZip), `.tgz`/`.tar.gz` (штатный `DecompressionStream`), `.tar`; вложенные — до двух
  уровней. Не читаем PDF, xlsx, docx, исходники САПР, картинки, 3D (`BIN` в коде). RAR и 7z — нет.
- **Папка**, перетащенная в зону, упаковывается в ZIP прямо в браузере (`folderToZip`, до 3000 файлов).
- **Отдельные файлы** определяются по содержимому. Больше трёх Gerber — одной строкой в списке;
  ненужные (отчёты САПР, апертуры) — строкой «Не нужны для расчёта».
- BOM (xlsx) не разбираем — см. §10.

### 3.2 Приоритет и отметки полей

Порядок: **IPC-2581 → ODB++ → ТЗ → .gbrjob → Pick&Place → Gerber**. Толщина и материал из ODB++ —
атрибуты САПР, там часто значения по умолчанию, поэтому они идут после ТЗ и получают «проверьте».

| Бейдж | Когда |
|---|---|
| «из …» (серый текст без плашки; Gerber-источники — «из Gerber», оценки — «оценка») | значение взято из источника |
| «расхождение» | источники дают разные значения — показаны оба, подставлено первое по приоритету |
| «проверьте» | значение из ODB++ (толщина, материал) или габариты, у которых отброшены выбросы контура |
| «ближайшее» | значения из файла нет в списке — подставлен ближайший пункт, пояснение над полем |
| «уточните» | не указано: покрытие → HASL, маркировка → белая |
| «заполните» | нет в файлах |
| «вручную» | клиент изменил поле после разбора |

Заголовок статуса — «Заполнено N из M параметров», под ним — сколько полей требуют внимания. Значок слева:
крутилка — разбираем, галочка — всё заполнено, «!» на золотом — есть поля, требующие внимания, «!» на
медном — расхождение или ошибка. Пустая страница до первого действия — без жёлтых «заполните» (`.cx.is-fresh`).
Значения в отчёте — как в полях («Зелёная», «FR-4, Tg 150»), а не как в файле.

### 3.3 Сопоставление со списками

- **Ближайшее значение** (`pick`) — толщина (допуск 0,03 мм), медь (2 мкм), слои (точно). Отличие больше
  допуска — отметка «ближайшее»: «В ТЗ 1,5 мм — такого нет в списке, считаем по ближайшему: 1,6 мм.»
- **Медь ODB++** округляется до стандартной: 35,56 мкм → 35.
- **Материал:** FR-4 с Tg ≥ 170 — High Tg, «FR-4 TG150» — обычный FR-4.
- **Покрытия:** HASL (стандарт), ENIG, ImAg, ENEPIG, Flashgold, Hardgold — по `finishMap`.

### 3.4 Проверка контура

Если точки контура лежат далеко за пределами меди (больше max(25 мм, 50 % размера меди)) — это
надпись, метка или второй объект на механическом слое; такие точки не учитываются, габариты — «проверьте».
Широкие поля без меди не обрезаются. У Altium несколько механических слоёв (`.GM1…GM16`): берётся слой
с лучшим признаком, среди равных — размер, который повторяется чаще.

## 4. Несколько плат в проекте ✅

### 4.1 Деление на платы

- **Gerber:** медные слои задают плату — по атрибуту X2 `TF.ProjectId` или `TF.SameCoordinates` (Altium
  пишет GUID на плату), иначе по общему началу имён файлов (`stemOf` снимает `-F_Cu`, `-RoundHoles`,
  «Pick Place for …» и т. п.). EasyEDA (у каждого слоя своё имя в одной папке) — одна плата.
  Остальные файлы — к плате с тем же именем, затем той же папки, затем к единственной.
- **IPC-2581 и ODB++** — по одной плате; к плате Gerber привязываются по габаритам и слоям.
- **ТЗ** — единственная плата → к ней; иначе по габаритам (± 1,5 мм), затем по словам из имени файла.
- Одинаковые копии одной платы (архив + те же файлы отдельно) не дублируются.
- **Названия:** имя «своего» ТЗ → отличающаяся часть имён файлов → папка без «Gerber» и дат → имя файла.

### 4.2 Комплект (по умолчанию)

- Карточки плат: размер, слои, компоненты, сумма; галочка «в заказе» и «× N в комплекте».
  Нажатие — параметры этой платы в этапах 2–3. Переключать плату можно и вкладками в начале этапов 2 и 3
  (`#calc-btabs-2`, `#calc-btabs-3`; длинные имена — с многоточием и подсказкой).
- У каждой платы свои параметры (`bstate[имя]`). Ещё не открытые платы заполняются из файлов «в тихом
  режиме» (`fillStates`); правки сохраняются при переключении. Смена набора файлов — параметры заново.
- Тираж — **число комплектов**; тираж платы = комплекты × штук в комплекте. Тираж из ТЗ не берётся.
- Итог — сумма по платам с разбивкой, «≈ … за комплект». Плата с расчётом инженером в сумму не входит
  (пометка); срок — по самой долгой плате; незаполненная плата — итог говорит, какая.
- На сервере — по запросу на плату в заказе (лимит сервера — 600 расчётов за 10 минут с адреса).

### 4.3 «Посчитать отдельно»

Кнопка под карточками: выбранная плата считается как обычная, без комплекта; тираж — штук этой платы
(при входе = комплекты × штук в комплекте, при возврате восстанавливается число комплектов). Нажатие
на другую карточку — отдельно её. В заявку уходит «посчитана отдельно — одна из N» и список всех плат.

## 5. Монтаж ✅

- **Быстрая оценка:** простые SMD, DIP-выводов, BGA, QFN/QFP и др. многовыводные.
- **Подробная:** группы корпусов (0201, 0402, 0603+, SOT/SOD, SOIC/TSSOP, QFP, QFN/DFN, BGA, DIP, разъёмы).
- Из IPC-2581 и ODB++ — точно, сразу подробная оценка. Из Pick&Place — подробная, если распознано ≥ 70 %
  корпусов, иначе быстрая; без посадочных мест разъёмы — по обозначениям X, J, P…, остальное — простые SMD.
- Только Gerber — грубо: площадки пасты / 2,4. Кнопки «Подставить» / «Сбросить».
- 0201 — расчёт инженером.

## 6. Расчёт ✅ (ставки демонстрационные)

- **В браузере** (`compute()`, ставки `R`) — пока в панели не опубликована формула. Подготовка,
  производство (площадь × ставка × множители × скидка объёма), монтаж (запуск, катушки, пайка), рентген,
  ПМИ и ОТК — «входит», доставка и таможня; вилка −15 / +20 %.
- **На сервере** — после публикации формулы плагин отдаёт `window.PCBCalcServer`; уходят только значения
  полей (`fieldData()`), не файлы. Ответ — вилка, строки, НДС, срок, `version`.
- **Расчёт инженером** — полиимид, ВЧ/СВЧ, > 16 слоёв, импеданс, слепые отверстия, via-in-pad, ламели,
  нестандартное покрытие, дорожка < 0,1 мм, отверстие < 0,2 мм, 0201.
- Срок: 6–8 недель; с инженерным расчётом — 2–3 месяца. Оценка не оферта — окончательная цена после аудита.

## 7. Связь с формой, черновиком и панелью ✅

### 7.1 `window.PCBCalc`

| Метод | Что отдаёт |
|---|---|
| `getSummary()` | Текстовая сводка для заявки: параметры, монтаж, оценка; в комплекте — блок по каждой плате |
| `getBrief()` | Короткая сводка для плашки формы: `params`, `estimate`, `files` |
| `getData()` | Структурированные данные → `calc_data` → `_pcb_calc` в заявке (§7.2) |
| `getFiles()` | Загруженные файлы — форма прикладывает их к заявке |
| `fingerprint()` | Отпечаток расчёта — форма видит, что он изменился после прикрепления |
| `isPending()`, `isUsed()`, `isRestoring()` | Идёт пересчёт / клиент что-то делал / восстанавливаем черновик |

### 7.2 Данные заявки (`getData()`)

Поля открытой платы: `qty, len, wid, layers, thick, cuout, cuin, mat, finish, mask, silk, track, hole,
sides, panel`, `special[]`, `asm`, `asm_values{}`, `finish_pending`; `estimate { lo, hi, per, vat }` или
`'engineer'`, `term`, `warn[]`, `calc_version`, `files[]`. Если плат несколько:
- `board` — открытая плата, `boards[] { name, size, layers, comps }`, `solo: true` — посчитана отдельно;
- `set { sets, boards[] { name, n, on, data, estimate } }` — комплект (нет в режиме «отдельно»);
  `estimate` верхнего уровня — за комплект, `qty` — число комплектов.

Подписи этих ключей в панели — `includes/crm/calc-labels.php` (для `board`, `boards`, `set` ❓ ещё нет).

### 7.3 События

- `pcb:calc` — расчёт изменился или пересчитывается (`detail.pending`); слушает форма.
- `pcb:track` — шаги для аналитики: `calc_upload`, `calc_result`, ошибки `calc_err` (`zip`, `tar`, `rar`,
  `ipc`, `xml`, `odb`, `format`).
- `pcb:draft-cleared` — форма отправлена, черновик удалён.
- `pcb:calc-attach` — клик по «Отправить на точный расчёт» в итоге (`detail.source = 'cta'`): форма может
  сама прикрепить расчёт (подписку добавляет чат формы).

### 7.4 Черновик и восстановление

- **Черновик** (`PCBDraft`, запись `calc`): поля, файлы, демо, выбранная плата, состояние комплекта
  (параметры плат, штук в комплекте, исключённые, «отдельно»). Плашка «Восстановили ваш расчёт…».
- **Из заявки** (`#pcb-restore`, кнопка «Показать в калькуляторе» в панели): файлы скачиваются по ссылкам
  панели (только у вошедшего), параметры — поверх; комплект и выбранная плата восстанавливаются.

## 8. Форма заявки на калькуляторе ✅

Подробно — шапка `request-form.js` и README панели §3. Особенности этапа 4:
- «Прикрепить данные из калькулятора» — снимок `getData()` + плашка из `getBrief()` + файлы калькулятора;
  описание задачи не трогается. Расчёт изменился после прикрепления — плашка предлагает обновить.
- Мягкие вопросы перед отправкой: пустое описание; считал, но не прикрепил; расчёт изменился.
- Поля формы (`#request`) на расчёт не влияют.

## 8a. Ввод чисел ✅

Габариты, дорожка и отверстие — текстовые поля `inputmode="decimal"` с запятой, как везде на сайте;
точку калькулятор заменяет на запятую при вводе. В данные (`fieldData()`, сервер, заявка) уходит точка.

## 9. Ограничения ✅

- Формула в браузере — демонстрационная; реальные ставки — в панели.
- Толщины в списке: 0,4 … 3,2 мм без 1,5 — значения не из списка идут через «ближайшее» (решение 2026-10-21).
- ODB++ со сжатыми `features.z` (Mentor, Cadence) — дорожка не определится.
- Тип монтажа по Pick&Place — эвристика по названиям посадочных мест (на DAC: 16 DIP против 18 по ODB++).
- Gerber без X2 и без ТЗ: контур определяется по расширению, покрытие и цвета — вручную.

## 10. Открытые вопросы ❓

- **BOM (xlsx):** даст число уникальных позиций (переналадка), стоимость и наличие компонентов, DNP.
  Технически доступно (xlsx — ZIP с XML), сложность — разные форматы колонок. Отложено.
- Подписи `board`, `boards`, `set`, `solo` в карточке заявки панели.
- Эталон из заявки в панели берёт данные только открытой платы.
- Селектор способа доставки на сайте — не решено (README панели §14).
