# Панель PCB Восток (`/panel`) — как устроено

Единое описание панели и всего, что через неё проходит: заявки, CRM, аналитика, SEO.
Источник истины — код в ветке `ivan_claude`; этот файл объясняет, *почему* код такой и *как* части связаны.

**Правило обновления.** Любой чат, который меняет плагин `pcb-panel`, обработчик заявок, форму заявки
(поля, отправку) или аналитику, в том же коммите правит этот файл: карту файлов, затронутый раздел
и, если принято решение, — журнал решений в конце. Перед работой с этими частями файл читается первым.

Статусы разделов: ✅ работает в коде · 🔧 решено, ещё не реализовано · ❓ открытый вопрос.

## 2. Адреса, вход и права ✅

- Адреса виртуальные (rewrite rules), это не страницы WordPress: их нет в «Страницах», меню и sitemap.
  `/panel` открывает первую разрешённую вкладку; неизвестная вкладка — 404, нет права — 403.
- Не вошёл → `auth_redirect()` на форму входа WordPress и возврат на тот же адрес.
- Ответ панели: `nocache_headers()`, `DONOTCACHEPAGE`, `X-Robots-Tag: noindex, nofollow`.
- `wp_head()` в каркасе не вызывается: стили темы и чужих плагинов в панель не попадают.
- Пользователь без `manage_options`: нет чёрной панели WordPress; `/wp-admin` → `/panel`,
  кроме `profile.php` (2FA) и `admin-post.php` (скачивание файлов заявок).

**Код проверяет права, а не роли.** Роль — только набор прав.

| Право | Смысл | Администратор | Менеджер |
|---|---|---|---|
| `pcb_panel_access` | Вход в панель | ✓ | ✓ |
| `pcb_crm_view` | Просмотр заявок и файлов | ✓ | ✓ |
| `pcb_crm_edit` | Статус, услуга, заметки | ✓ | ✓ |
| `pcb_crm_delete` | Удаление, выгрузка, удаление данных клиента | ✓ | — |
| `pcb_panel_log_view` | Общий журнал действий | ✓ | — |
| `pcb_analytics_view` | Аналитика | ✓ | ✓ |
| `pcb_seo_view` / `pcb_seo_edit` | SEO: просмотр / правка | ✓ / ✓ | ✓ / — |

Права типа записей (`edit_pcb_requests`, `read_pcb_requests`…) есть только у администратора — они нужны
лишь для раздела «Заявки» в админке WordPress. Панель и скачивание файлов проверяют права панели:
файл — `pcb_crm_view`, правки — `pcb_crm_edit`, удаление и выгрузка — `pcb_crm_delete`.

Роли пересоздаются автоматически, когда меняется `PCB_PANEL_VERSION` (сравнение с опцией
`pcb_panel_roles_version`). **Изменил набор прав — подними версию плагина.**

## 3. Заявки: от формы до панели

### 3.1 Приём ✅

`POST /wp-json/pcb/v1/request` (multipart). Порядок проверок:
ловушка `pcb_hp_check` → не больше 5 заявок с IP за 10 минут (transient по md5 IP) → почта →
согласие → капча SmartCaptcha (`failed` — отказ; сервис недоступен — `unchecked`, заявка принимается) →
файлы (до 10 шт., до 50 МБ вместе, без исполняемых) → «описание или хотя бы один файл».
Неудачи пишутся обезличенным событием `form_err` в аналитику.

### 3.2 Запись ✅

Тип записей `pcb_request`, статус `private`, заголовок «Заявка <номер> — <компания или почта>»,
текст записи — описание задачи.

| Метаполе | Содержимое |
|---|---|
| `_pcb_number` | Внутренний номер `ГГГГ-NNNN` — только для админки и панели |
| `_pcb_code` | Код для клиента: 6 шестнадцатеричных символов, заглавные, уникальный, напр. `7F3A9C` |
| `_pcb_status` | `new` · `work` · `done` · `lost` (см. 3.4) |
| `_pcb_lost_reason` | Причина отказа, необязательная |
| `_pcb_service` | Услуга, текущая (может исправить менеджер) |
| `_pcb_service_client` | Услуга, которую выбрал клиент; не меняется |
| `_pcb_email`, `_pcb_phone`, `_pcb_name`, `_pcb_company` | Контакты из формы |
| `_pcb_source` | `home` / `calc` |
| `_pcb_files` | Массив `{key, name, size, path}`; `path` относительно `active/`. У файлов из панели ещё `kind` (`manager` — добавил менеджер, `sent` — вложение письма клиенту), `by` (ID пользователя), `added` (время) |
| `_pcb_calc` | JSON `PCBCalc.getData()`; в панели выводится как есть, списком «параметр — значение» |
| `_pcb_captcha` | `ok` / `unchecked` / `disabled` |
| `_pcb_page`, `_pcb_referrer`, `_pcb_utm` | Откуда пришла заявка |
| `_pcb_consent` | Время, IP, браузер, ссылки на политику, `PCB_POLICY_VERSION`. IP хранится осознанно — доказательство согласия |
| `_pcb_mail` | Результат отправки писем: `notify`, `client` |
| `_pcb_seen` | Когда и кем заявка впервые открыта в панели (для пометки «новая») |
| `_pcb_original` | Исходные контакты из формы `{email, phone, name, company}` — не меняются никогда; текущие значения — в полях выше |
| `_pcb_ym_client` | ClientID Яндекс Метрики (только цифры), если посетитель согласился на аналитику; иначе пусто |

### 3.3 Номера ✅

- Внутренний `ГГГГ-NNNN`: счётчик в опции `pcb_request_counter_<год>`, увеличивается одним SQL-запросом
  (`UPDATE … LAST_INSERT_ID(…)`), плюс проверка, что такого номера ещё нет. Если база не поддерживает
  этот приём (так бывает на тестовой SQLite) — запасной путь через `get_option`/`update_option`.
- Код клиента `_pcb_code`: генерируется при создании, при совпадении — заново. ~16,7 млн вариантов.
  Может состоять только из цифр (это тоже шестнадцатеричное число).
  Ни к чему не даёт доступа — только метка для переписки.
- Клиент видит **только код**: экран «Заявка отправлена» (`{номер}` в тексте блока), тема и текст
  письма «заявка получена». Менеджер в письме и панели видит оба: «2026-0012 · для клиента 7F3A9C».
  Поиск в панели — по обоим.
- Старым заявкам код присваивается при обновлении (`migrate.php`).
- Карточка открывается и по номеру, и по коду: `/panel/crm/7F3A9C/` перенаправляет на `/panel/crm/2026-0012/`.

### 3.4 Статусы и услуги ✅

Четыре статуса (решение — менеджеры не будут вести длинную воронку):

| Код | Название | Миграция старых |
|---|---|---|
| `new` | Новая | `new` |
| `work` | В работе | `work`, `quoted` |
| `done` | Завершена | `closed` |
| `lost` | Отказ (+ необязательная причина) | — |

Списки — константы `PCB_RQ_STATUSES` и `PCB_RQ_LOST_REASONS` в `handler.php`. Причины отказа: дорого, не устроили сроки, не можем сделать, клиент не ответил, другое.

Услуга — радио `service` в форме. Известные коды: `turnkey` (Платы под ключ), `pcb` (Только платы),
`components` (Только компоненты), `other` (Другое). Варианты правятся в редакторе страницы; незнакомое
значение сохраняется текстом как есть и так же показывается в панели. Менеджер может исправить услугу;
выбор клиента остаётся в `_pcb_service_client` и виден в карточке и истории.

### 3.5 Файлы ✅

Хранятся вне веб-корня; путь вычисляется от `public_html`, `wp-config.php` править не нужно.
Случайные имена `.bin`, права 0640, в каждой папке `.htaccess` с запретом на случай веб-доступа.

```
<папка сайта>/
├── public_html/
└── pcb-data/requests/
    ├── active/<номер>/            файлы действующих заявок
    └── archive/<номер>_<код>/     файлы удалённых заявок + info.txt
```

- Выбранный корень запоминается в опции `pcb_rq_storage_root`. Константа `PCB_REQUEST_STORAGE` (полный путь
  к корню, внутри будут `active/` и `archive/`) имеет приоритет.
- Если PHP не может писать выше `public_html`, корень — `uploads/pcb-requests/` (защищён `.htaccess`, прямой URL
  отдаёт 403 — проверено на сервере), а администратор видит предупреждение в CRM и на «Проверке почты».
- До 0.3.0 файлы лежали в `uploads/pcb-requests/<номер>/`; при обновлении они переносятся в `active/`, пустая
  старая папка удаляется. Скачивание — только через
`admin-post.php?action=pcb_request_file&id=<ID>&f=<key>` с проверкой права.

### 3.6 Письма ✅

- Менеджерам (`PCB_REQUEST_NOTIFY`): контакты, услуга, описание, **только ссылки** на файлы, Reply-To — клиент.
  Тема письма: «Новая заявка 2026-0012 (7F3A9C) · услуга»; «Открыть заявку» ведёт на карточку в панели.
- Клиенту: «Заявка № <код> получена» — только код.
- SMTP через `phpmailer_init`, если задан `PCB_SMTP_HOST`. Страница «Заявки → Проверка почты» — тест и журнал SMTP.

## 4. Журнал изменений заявок ✅

Отдельная таблица `{prefix}pcb_request_log` — переживает удаление заявки и даёт общий журнал одним запросом.

| Поле | Содержимое |
|---|---|
| `id` | Автоинкремент |
| `time` | Дата и время |
| `user_id` | Кто (0 — система или сайт) |
| `request_id`, `number`, `code` | Какая заявка (номер и код дублируются, чтобы запись читалась после удаления) |
| `action` | `created`, `status`, `lost_reason`, `service`, `contact`, `note`, `note_important`, `note_resolved`, `file_added`, `file_download`, `email`, `export`, `deleted`, `deleted_archived`, `migrated` |
| `old_value`, `new_value` | Было / стало; для заметки `new_value` — текст, `old_value` — флаг (`''`, `important`, `resolved`); для письма `new_value` — JSON `{subject, body, files}`; для `contact` — только названия изменённых полей, без значений |

**Контактов клиента в журнале нет** — поэтому он может храниться после удаления заявки.
Заметки и письма хранятся только в журнале (отдельных метаполей нет). В их текстах могут быть персональные
данные, поэтому при удалении заявки тексты заметок и писем стираются (`pcb_crm_scrub_log()`), остаётся факт действия.
Правка контактов пишется без значений («Исправлены контакты: Имя») — сами значения видны только в карточке.
Все изменения идут через одну функцию, которая и пишет журнал, — из панели и из админки WordPress одинаково.
Видно: история заявки — в карточке (панель и админка); общий журнал — в панели у администратора.

## 5. Удаление и архив ✅

Удаление — только с `pcb_crm_delete` (администратор). Окно подтверждения с выбором:
- «Удалить заявку и файлы» — безвозвратно;
- «Удалить заявку, файлы — в архив» — запись удаляется из базы, папка переезжает в `archive/<номер>_<код>/`
  с `info.txt`: номер, код, дата, услуга, кто и когда удалил, список файлов. Контактов нет.

Архив проверяется на персональные данные и чистится вручную. Удаление мимо панели (окончательное удаление
из корзины в админке WordPress) **уводит файлы в архив** — так проектные данные не теряются случайно.

## 6. CRM в панели ✅

- **Список** `/panel/crm`: номер, код, дата, клиент, услуга, статус, файлы, источник; фильтр по статусу,
  поиск по номеру и коду (точно) и по почте, компании, имени, телефону (по части); по 50 на страницу;
  непросмотренные отмечены медной полосой и словом «новая», их число — на вкладке CRM. «Просмотрена» —
  после первого открытия карточки любым пользователем (`_pcb_seen`).
- **Карточка** `/panel/crm/<номер>`: слева — что прислал клиент (описание, данные калькулятора, файлы);
  справа — статус, услуга (с выбором клиента), заметки, история; «Ответить» — `mailto:` с кодом в теме;
  внизу — другие заявки с той же почты или компании.
- **Клиент**: менеджер правит почту, телефон, имя и компанию; исправленное поле — медным, под ним серым
  «В заявке: …» (из `_pcb_original`). Письма уходят на текущую почту. Описание задачи не правится.
- **Описание задачи** и **данные калькулятора** — сворачиваемые блоки: длинные (больше 600 знаков / 8 строк)
  свёрнуты по умолчанию. История и «Служебное» — тоже сворачиваются.
- **Данные калькулятора** — с названиями со страницы калькулятора (`calc-labels.php`): подписи полей, варианты
  списков, режим монтажа, строки и столбцы таблицы «Группа корпусов». Страница находится по разметке
  (`data-key="qty"` и `name="asm"`), разбор кешируется до её следующего сохранения; если страницы нет — запасные
  подписи в коде. Новые ключи калькулятора, которых плагин не знает, выводятся как есть.
- **Файлы**: менеджер добавляет файлы (например, досланные клиентом на почту) — те же проверки, что у формы.
  У файла видно, кто и когда его добавил; вложения писем помечены «отправлено клиенту».
- **Заметки**: галочка «Важно». Важная заметка подсвечена и стоит первой, пока отметку не снимут
  («Снять «Важно»»); снятие — в истории. В списке заявок у номера — значок «!», если есть открытые важные заметки.
- **Письмо клиенту** — кнопка «Ответить» открывает отдельное окно: тема «Заявка № <код> — PCB Восток»,
  текст, подпись менеджера, вложения (файлы заявки и новые, до 20 МБ вместе; новые сохраняются в заявке).
  From и Reply-To — общий ящик `PCB_MAIL_FROM`, скрытая копия — туда же (SMTP не кладёт письмо в «Отправленные»).
  Отправленные письма — в разделе «Переписка». Ответы клиента приходят в почту, в CRM не попадают.
- **Мой профиль** `/panel/profile/` (ссылка — имя в шапке): подпись в письмах, своя у каждого пользователя
  (`user_meta pcb_mail_signature`); по умолчанию — «С уважением, <имя>, PCB Восток, <сайт>».
- **Только администратор**: выгрузка CSV (`;`, UTF-8 с BOM, значения из формы защищены от формул Excel),
  удаление (§5), общий журнал `/panel/crm/journal/`. 🔧 «Удалить данные клиента» — не реализовано.
- Правки — через REST `pcb-panel/v1/...` с `permission_callback` на каждое право и nonce `wp_rest`.
- Раздел «Заявки» в админке WordPress остаётся как запасной вход для администратора.

## 7. Аналитика ✅

### 7.1 Связь заявки с Яндекс Метрикой ✅

- Только если посетитель согласился на аналитические cookie (`PCBConsent.get() === 'all'`), иначе Метрика
  не загружается и связи нет.
- При отправке формы `request-form.js` берёт `ym(<счётчик>, 'getClientID')` (ждёт до 0,8 с) и шлёт
  `ym_client_id`; обработчик сохраняет его в `_pcb_ym_client`.
- После успешной отправки — `ym(<счётчик>, 'userParams', { pcb_request: <код> })`: в Метрике визиты ищутся
  по коду заявки. Контакты в Яндекс не передаются — только случайный код.
- В карточке — блок «Яндекс Метрика»: ClientID и код (копируются по клику), ссылки на отчёты «Посетители»,
  «Вебвизор», «Параметры посетителей». ❓ Ссылки ведут на отчёты целиком — отбор по ClientID делается сегментом
  в Метрике; прямую ссылку с фильтром проверить на рабочем счётчике.
- Ограничения: ClientID привязан к браузеру (разные устройства — разные истории). Собственная аналитика
  панели (§7, таблица событий) остаётся обезличенной и с заявками не связывается — намеренно.

- Собственные события: таблица `{prefix}pcb_events` (день + событие + значение + количество), без IP,
  cookie и идентификаторов. Белый список событий — `pcb_events_whitelist()`. Браузер шлёт на
  `POST pcb-panel/v1/e`, сервер — `do_action( 'pcb_event', $event, $value )`. Хранится 2 года, чистка ежедневно.
- Яндекс.Метрика и Вебмастер — через API (`yandex.php`), данные кешируются; Метрика на сайте грузится
  только после согласия на cookie.
- Подробности модуля дописывает чат аналитики.

## 10. Деплой

- Плагин лежит в репозитории рядом с темой и доставляется на сайт тем же путём (Gitium); после первого
  появления — активировать в «Плагинах».
- Изменились права или структура данных — поднять `PCB_PANEL_VERSION`: роли и миграции применятся сами.
- Таблицы создаются через `dbDelta` по своей версии (`pcb_events_db_version`, `pcb_request_log_db_version`),
  данные заявок обновляются по `pcb_rq_data_version`, правила адресов пересобираются при смене версии плагина.
- **Плагин должен быть активен**: форма заявки отправляет данные на его адрес `pcb/v1/request`; если плагин
  выключен, форма покажет ошибку отправки.
- `wp-content/updraft/` и `wp-content/uploads/` не попадают в git (`.gitignore`).
- Проверено на чистом WordPress + SQLite: приём, отказ для исполняемых файлов и пустых заявок, хранение вне
  веб-корня, права менеджера и администратора, правки и nonce, удаление в архив/безвозвратно/из корзины,
  выгрузка CSV, миграция старых заявок; в 0.4.0 — подписи калькулятора по настоящей странице, правка контактов,
  загрузка файлов, важные заметки, письмо с подписью и вложениями (перехват почты), стирание текстов при удалении.

## 11. Правила разработки

1. Права, а не роли; у каждого REST-эндпоинта свой `permission_callback`.
2. Скрытая кнопка — не защита: изменение проверяется на сервере.
3. Персональные данные не уходят третьим лицам и не пишутся в журналы и аналитику.
4. Хранение заявок — в плагине; тема отвечает только за вид формы.
5. Не дублировать данные: CRM читает те же записи `pcb_request`, что создаёт форма.
6. Изменил поведение — обнови этот файл в том же коммите.
