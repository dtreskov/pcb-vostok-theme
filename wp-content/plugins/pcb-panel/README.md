# Панель PCB Восток (`/panel`) — как устроено

Единое описание панели и всего, что через неё проходит: заявки, CRM, аналитика, SEO, калькулятор.
Источник истины — код в ветке `ivan_claude`; этот файл объясняет, *почему* код такой и *как* части связаны.

**Правило обновления.** Любой чат, который меняет плагин `pcb-panel`, обработчик заявок, форму заявки
(поля, отправку) или аналитику, в том же коммите правит этот файл: карту файлов, затронутый раздел
и, если принято решение, — журнал решений в конце. Перед работой с этими частями файл читается первым.

Статусы разделов: ✅ работает в коде · 🔧 решено, ещё не реализовано · ❓ открытый вопрос.

## 2. Адреса, вход и права ✅

- Адреса виртуальные (rewrite rules), это не страницы WordPress: их нет в «Страницах», меню и sitemap.
  `/panel` открывает первую разрешённую вкладку; неизвестная вкладка — 404, нет права — 403.
- Не вошёл → `auth_redirect()` на форму входа WordPress и возврат на тот же адрес.
- Ответ панели: `nocache_headers()`, `DONOTCACHEPAGE`, `X-Robots-Tag: noindex, nofollow`.
- `wp_head()` в каркасе не вызывается: стили темы и чужих плагинов в панель не попадают.
- **Кнопки**: прижаты вправо; если в группе только кнопки и их несколько — одинаковой ширины (`.crm-form__acts`,
  `.crm-dialog__actions`, `.crm-head-actions`); пояснение в той же строке — слева. На телефоне группа — столбиком.
- **Часовой пояс**: время в панели — по часовому поясу WordPress. Если там UTC, администратор видит над панелью
  подсказку «Настройки → Общие → Часовой пояс: Москва».
- В шапке — кнопка «Сайт» (главная в новой вкладке; на телефоне — только значок), рядом с ролью и меню пользователя.
- Пользователь без `manage_options`: нет чёрной панели WordPress; `/wp-admin` → `/panel`,
  кроме `profile.php` (2FA) и `admin-post.php` (скачивание файлов заявок).

**Код проверяет права, а не роли.** Роль — только набор прав.

| Право | Смысл | Администратор | Менеджер |
|---|---|---|---|
| `pcb_panel_access` | Вход в панель | ✓ | ✓ |
| `pcb_crm_view` | Просмотр заявок и файлов | ✓ | ✓ |
| `pcb_crm_edit` | Статус, услуга, заметки | ✓ | ✓ |
| `pcb_crm_delete` | Удаление, выгрузка, удаление данных клиента | ✓ | — |
| `pcb_panel_log_view` | Общий журнал действий | ✓ | — |
| `pcb_analytics_view` | Аналитика | ✓ | ✓ |
| `pcb_seo_view` / `pcb_seo_edit` | SEO и техработы: просмотр / правка | ✓ / ✓ | ✓ / — |
| `pcb_calc_view` / `pcb_calc_edit` | Калькулятор: просмотр формулы / правка и публикация | ✓ / ✓ | ✓ / ✓ |

Права типа записей (`edit_pcb_requests`, `read_pcb_requests`…) есть только у администратора — они нужны
лишь для раздела «Заявки» в админке WordPress. Панель и скачивание файлов проверяют права панели:
файл — `pcb_crm_view`, правки — `pcb_crm_edit`, удаление и выгрузка — `pcb_crm_delete`.

Роли пересоздаются автоматически, когда меняется `PCB_PANEL_VERSION` (сравнение с опцией
`pcb_panel_roles_version`). **Изменил набор прав — подними версию плагина.**

## 3. Заявки: от формы до панели

### 3.1 Приём ✅

`POST /wp-json/pcb/v1/request` (multipart). Порядок проверок:
ловушка `pcb_hp_check` → не больше 5 заявок с IP за 10 минут (transient по md5 IP) → почта →
согласие → капча SmartCaptcha (`failed` — отказ; сервис недоступен — `unchecked`, заявка принимается) →
файлы (до 20 шт., до 100 МБ вместе, без исполняемых — `PCB_RQ_MAX_FILES`, `PCB_RQ_MAX_TOTAL`; в форме те же
числа — `MAX_FILES`, `MAX_TOTAL` в `request-form.js`) → «описание, хотя бы один файл или прикреплённый расчёт калькулятора»
(расчёт засчитывается, если в нём есть тираж, размеры, слои или оценка — `pcb_rq_calc_filled()`).
Неудачи пишутся обезличенным событием `form_err` в аналитику.

**Хостинг:** чтобы заявка на 100 МБ доходила до кода, в PHP `post_max_size` и `upload_max_filesize` — не меньше
110M (и `client_max_body_size` у nginx, если он стоит перед PHP); иначе запрос отклоняется до WordPress и форма
показывает «Не удалось отправить заявку». Те же лимиты — для загрузки файлов менеджером в карточке (до 20 файлов
и 100 МБ за раз; всего на заявку — до 500 МБ).

### 3.2 Запись ✅

Тип записей `pcb_request`, статус `private`, заголовок «Заявка <номер> — <компания или почта>»,
текст записи — описание задачи.

| Метаполе | Содержимое |
|---|---|
| `_pcb_number` | Внутренний номер `ГГГГ-NNNN` — только для админки и панели |
| `_pcb_code` | Код для клиента: 6 шестнадцатеричных символов, заглавные, уникальный, напр. `7F3A9C` |
| `_pcb_status` | `new` · `work` · `done` · `lost` (см. 3.4) |
| `_pcb_lost_reason` | Причина отказа, необязательная |
| `_pcb_service` | Услуга, текущая (может исправить менеджер) |
| `_pcb_service_client` | Услуга, которую выбрал клиент; не меняется |
| `_pcb_email`, `_pcb_phone`, `_pcb_name`, `_pcb_company` | Контакты из формы |
| `_pcb_source` | `home` / `calc` |
| `_pcb_files` | Массив `{key, name, size, path}`; `path` относительно `active/`. У файлов из панели ещё `kind` (`manager` — добавил менеджер, `sent` — вложение письма клиенту), `by` (ID пользователя), `added` (время) |
| `_pcb_calc` | Снимок `PCBCalc.getData()` на момент прикрепления в форме (поле `calc_data`). Единственный источник расчёта: описание задачи — только слова клиента. Сервер пропускает только известные поля и укорачивает строки (`pcb_rq_clean_calc()` → `pcb_rq_clean_calc_data()`, не больше 64 КБ), в том числе ключи нескольких плат — `board`, `boards[]`, `solo`, `set`, `asm_est` (§3.9). Оценка — `estimate: {lo, hi, per, vat}` (`vat` — ставка НДС, если оценка показана с НДС) или `'engineer'` |
| `_pcb_captcha` | `ok` / `unchecked` / `disabled` |
| `_pcb_page`, `_pcb_referrer`, `_pcb_utm` | Откуда пришла заявка |
| `_pcb_consent` | Время, IP, браузер, ссылки на политику, `PCB_POLICY_VERSION`. IP хранится осознанно — доказательство согласия |
| `_pcb_mail` | Результат отправки писем: `notify`, `client` |
| `_pcb_seen` | Когда и кем заявка впервые открыта в панели (для пометки «новая») |
| `_pcb_original` | Исходные контакты из формы `{email, phone, name, company}` — не меняются никогда; текущие значения — в полях выше |
| `_pcb_k_email`, `_pcb_k_phone`, `_pcb_k_company` | Ключи сравнения для связанных заявок (почта в нижнем регистре; цифры телефона, 8/без кода → 7; компания без формы собственности, кавычек и регистра). Пересчитываются при поступлении и правке (`pcb_crm_reindex()`) |
| `_pcb_contact_id`, `_pcb_company_id`, `_pcb_client_link` | Клиент заявки (§6.1): контакт, компания, как привязана — `auto` / `manual` |
| `_pcb_ym_client` | ClientID Яндекс Метрики (только цифры), если посетитель согласился на аналитику; иначе пусто |

### 3.3 Номера ✅

- Внутренний `ГГГГ-NNNN`: счётчик в опции `pcb_request_counter_<год>`, увеличивается одним SQL-запросом
  (`UPDATE … LAST_INSERT_ID(…)`), плюс проверка, что такого номера ещё нет. Если база не поддерживает
  этот приём (так бывает на тестовой SQLite) — запасной путь через `get_option`/`update_option`.
- Код клиента `_pcb_code`: генерируется при создании, при совпадении — заново. ~16,7 млн вариантов.
  Может состоять только из цифр (это тоже шестнадцатеричное число).
  Ни к чему не даёт доступа — только метка для переписки.
- Клиент видит **только код**: экран «Заявка отправлена» (`{номер}` в тексте блока), тема и текст
  письма «заявка получена». Менеджер в письме и панели видит оба: «2026-0012 · для клиента 7F3A9C».
  Поиск в панели — по обоим.
- Старым заявкам код присваивается при обновлении (`migrate.php`).
- Карточка открывается и по номеру, и по коду: `/panel/crm/7F3A9C/` перенаправляет на `/panel/crm/2026-0012/`.

### 3.4 Статусы и услуги ✅

Четыре статуса (решение — менеджеры не будут вести длинную воронку):

| Код | Название | Миграция старых |
|---|---|---|
| `new` | Новая | `new` |
| `work` | В работе | `work`, `quoted` |
| `done` | Завершена | `closed` |
| `lost` | Отказ (+ необязательная причина) | — |

Списки — константы `PCB_RQ_STATUSES` и `PCB_RQ_LOST_REASONS` в `handler.php`. Причины отказа: дорого, не устроили сроки, не можем сделать, клиент не ответил, другое.

Услуга — радио `service` в форме. Известные коды: `turnkey` (Платы под ключ), `pcb` (Только платы),
`components` (Только компоненты), `other` (Другое). Варианты правятся в редакторе страницы; незнакомое
значение сохраняется текстом как есть и так же показывается в панели. Менеджер может исправить услугу;
выбор клиента остаётся в `_pcb_service_client` и виден в карточке и истории.

### 3.5 Файлы ✅

Хранятся вне веб-корня; путь вычисляется от `public_html`, `wp-config.php` править не нужно.
Случайные имена `.bin`, права 0640, в каждой папке `.htaccess` с запретом на случай веб-доступа.

```
<папка сайта>/
├── public_html/
└── pcb-data/requests/
    ├── active/<номер>/            файлы действующих заявок
    └── archive/<номер>_<код>/     файлы удалённых заявок + info.txt
```

- Выбранный корень запоминается в опции `pcb_rq_storage_root`. Константа `PCB_REQUEST_STORAGE` (полный путь
  к корню, внутри будут `active/` и `archive/`) имеет приоритет.
- Если PHP не может писать выше `public_html`, корень — `uploads/pcb-requests/` (защищён `.htaccess`, прямой URL
  отдаёт 403 — проверено на сервере), а администратор видит предупреждение в CRM и на «Проверке почты».
- До 0.3.0 файлы лежали в `uploads/pcb-requests/<номер>/`; при обновлении они переносятся в `active/`, пустая
  старая папка удаляется. Скачивание — только через
`admin-post.php?action=pcb_request_file&id=<ID>&f=<key>` с проверкой права.

### 3.6 Письма ✅

- Менеджерам (`PCB_REQUEST_NOTIFY`): контакты, услуга, описание, блок «Данные калькулятора» (из `_pcb_calc`, те же подписи,
  что в карточке, — `pcb_crm_calc_rows()`), **только ссылки** на файлы, Reply-To — клиент.

### 3.7 Данные калькулятора в форме ✅ (0.8.1, поведение — 0.8.2)

Только на странице калькулятора (этап 4); на главной калькулятора нет — там подсказка со ссылкой на него.

- **Расчёт прикладывается сам** (0.8.2): как только клиент пользовался калькулятором (`PCBCalc.isUsed()` —
  загрузил файлы или поменял поле), пилюля — «Расчёт и файлы прикреплены» («Расчёт прикреплён к заявке», если файлов нет или они откреплены), файлы калькулятора — в списке файлов формы
  с пометкой «из калькулятора». Плашка под пилюлей (стрелка или сама пилюля) — «В заявку уйдёт:» и две галочки:
  - **«Предварительный расчёт»** — сводка `getBrief()` вживую по событию `pcb:calc` («4 слоя · 80 × 55 мм · 250 шт · ENIG · …»,
    оценка «… ₽ · в т. ч. НДС 22 %», при пересчёте — «считается…») и спойлер «Все данные расчёта» с полным текстом
    `getSummary()` (без строки о файлах). Снята — `calc_data` не отправляется, пилюля «Файлы калькулятора прикреплены»;
  - **«Файлы из калькулятора»** — их имена; снята — файлы калькулятора не прикрепляются («… — не прикрепляются»).
  Сняты обе — из калькулятора ничего не уходит, пилюля «Прикрепить данные из калькулятора»; она же, ссылка
  «Прикрепить» над зоной файлов и «Отправить на точный расчёт» в итоге калькулятора (`pcb:calc-attach`, раскрывает
  плашку) возвращают обе галочки. Ниже — «Изменить в калькуляторе».
- В заявку уходит снимок `getData()` **в момент отправки** (`calc_data`) — то, что клиент видит в итоге;
  во время «считается…» отправка ждёт ответа сервера до 10 с. Описание задачи — только слова клиента.
- Крестик у файла калькулятора в списке убирает его только из заявки (в калькуляторе остаётся). Состояние
  галочек хранится в черновике формы (§3.8).
- **Дубли:** файл, который уже есть в калькуляторе (имя и размер), в форму не добавляется; под зоной —
  ««…» уже в заявке — из калькулятора» или, если расчёт убран, «загружен в калькулятор» + «Прикрепить вместе с расчётом».
- **Зона файлов формы:** подпись «Файлы проекта», если в калькуляторе есть файлы — «Другие файлы к заявке»;
  над зоной — «Файлы из калькулятора уже в заявке. Здесь добавьте то, чего в них нет, — например BOM или чертёж.»
  (файлы откреплены — «Файлы из калькулятора в заявку не входят. Прикрепить»; ничего не прикреплено —
  «Расчёт и файлы из калькулятора (…) в заявку не входят. Прикрепить»). Подсказка — «Gerber,
  BOM, чертежи, ТЗ — архивом или по отдельности. До 20 файлов, до 100 МБ вместе.»; под зоной — «Больше 100 МБ —
  пришлите на почту … или вставьте ссылку на облако в описание задачи». Зона компактная, как в этапе 1; когда
  файлы есть — переезжает в строку «N файлов — приложено к заявке» справа («Добавить ещё файлы», без подсказки:
  состав — в строке над зоной, объём — в статусе), на телефоне — под статусом (`placeDrop()`).
- Мягкий вопрос перед отправкой — только пустое описание («Дополнить описание» / «Отправить без описания»,
  и на главной). Вопросы «считал, но не прикрепил» и «расчёт изменился» (0.8.1) убраны вместе с состоянием
  «Расчёт изменился».
- Согласие на обработку данных — над кнопкой «Отправить заявку», капча — столбцом справа на высоту согласия и
  кнопки (на главной так же; на телефоне: согласие, капча, кнопка).

### 3.9 Несколько плат в заявке ✅ (0.8.2)

Калькулятор делит проект на платы и по умолчанию считает **комплект** (устройство — `docs/calculator.md` темы,
§4 и §7.2). Поля верхнего уровня `_pcb_calc` — открытой платы, как раньше; дополнительно:
`board`, `boards[] {name, size, layers, comps}`, `solo` («посчитана отдельно»), `asm_est` (монтаж — оценка),
`set {sets, ship, saving, boards[] {name, n, on, data, estimate {lo, hi, per, goods}}}`. В комплекте `qty` = число
комплектов, `estimate.per` — за комплект.

- **Приём** — `pcb_rq_clean_calc_data()`: `data` каждой платы комплекта проверяется тем же фильтром, что и плата
  верхнего уровня; до 20 плат; `set` при `solo` отбрасывается.
- **Письмо и карточка** — `pcb_crm_calc_rows()` (`calc-labels.php`): «Комплект: 20 комплектов, плат в заказе 3 из 4»;
  по каждой плате «Плата «main»: 1 в комплекте, всего 20 шт», её поля вложенными строками и «Оценка платы без
  доставки»; «не в заказе» — без полей; «Доставка и таможня одной партией ≈ … (экономия …)»; оценка «≈ … за
  комплект». «Отдельно» — «Плата: «X» посчитана отдельно — одна из N». Для нескольких плат — «Платы проекта: …».
  Оценочный монтаж — «(оценка: компоненты не учтены поштучно)». Поля одной платы — `pcb_crm_calc_board_rows()`.
- **«Показать в калькуляторе»** передаёт `_pcb_calc` целиком — калькулятор восстанавливает комплект и открытую плату.
- ❓ Расчёт комплекта на сервере (`calc/quote` считает одну плату) и эталон-комплект — §14.

### 3.8 Черновик формы и калькулятора в браузере ✅ (тема, 2026-10-20)

Чтобы введённое не терялось при переходе между страницами (главная ↔ калькулятор, клик по ссылке), тема хранит
черновик **только в браузере посетителя** — `assets/js/form-draft.js` (`window.PCBDraft`), IndexedDB, база `pcb-draft`.
На сервер черновик не уходит; описано в `/politics#cookies-8`.

- Запись `form` (`request-form.js`): поля формы, кроме согласия, ловушки и капчи; файлы (с меткой «из калькулятора»);
  прикреплённый расчёт — снимок без `pending`. Общая для главной и калькулятора: на главной расчёт и файлы калькулятора
  не показываются, но сохраняются. При восстановлении над формой — «Восстановили незаконченную заявку от … · Очистить форму».
- Запись `calc` (`calculator.js`): значения полей (`fieldData()`), файлы, имена демо-файлов. Пишется, только если клиент
  пользовался калькулятором. При восстановлении файлы разбираются заново (без цели `calc_upload`), затем поверх
  ставятся значения клиента; изменённые после разбора поля — «вручную». Плашка «Восстановили ваш расчёт … · Начать заново».
  Пока идёт восстановление, `PCBCalc.isRestoring()` = true и форма не сверяет отпечаток; после — снимок тот же →
  обновляется, другой → «Расчёт изменился».
- Срок — 7 дней (`PCBDraft.ttlDays`), удаляются после успешной отправки (обе записи), по «Очистить форму» (`form`),
  «Начать заново» (`calc`). Расчёт, открытый из панели (`#pcb-restore`), не подставляется и не сохраняется.
- Нет IndexedDB (приватный режим) — запасной `localStorage` без файлов; плашка просит приложить файлы заново.
- Ссылки на согласие и политику в форме открываются в новой вкладке.

## 4. Журнал изменений заявок ✅

Отдельная таблица `{prefix}pcb_request_log` — переживает удаление заявки и даёт общий журнал одним запросом.

| Поле | Содержимое |
|---|---|
| `id` | Автоинкремент |
| `time` | Дата и время |
| `user_id` | Кто (0 — система или сайт) |
| `request_id`, `number`, `code` | Какая заявка (номер и код дублируются, чтобы запись читалась после удаления) |
| `action` | `created`, `status`, `lost_reason`, `service`, `contact`, `note`, `note_important`, `note_resolved`, `file_added`, `file_download`, `email`, `export`, `deleted`, `deleted_archived`, `migrated` |
| `old_value`, `new_value` | Было / стало; для заметки `new_value` — текст, `old_value` — флаг (`''`, `important`, `resolved`); для письма `new_value` — JSON `{subject, body, files}`; для `contact` — `old_value` = поле, `new_value` = JSON `{field, old, new}` |

**Контактов клиента в журнале нет** — поэтому он может храниться после удаления заявки.
Заметки и письма хранятся только в журнале (отдельных метаполей нет). В их текстах могут быть персональные
данные, поэтому при удалении заявки тексты заметок и писем стираются (`pcb_crm_scrub_log()`), остаётся факт действия.
Правка контактов пишется «было → стало» по каждому полю (с 0.5.0); при удалении заявки значения стираются,
остаётся «Исправлено поле «Имя»». Смена отображаемого имени пользователя — действие `user_name` (без заявки).
Все изменения идут через одну функцию, которая и пишет журнал, — из панели и из админки WordPress одинаково.
Видно: история заявки — в карточке (панель и админка); общий журнал — в панели у администратора.

## 5. Удаление и архив ✅

Удаление — только с `pcb_crm_delete` (администратор). Окно подтверждения с выбором:
- «Удалить заявку и файлы» — безвозвратно;
- «Удалить заявку, файлы — в архив» — запись удаляется из базы, папка переезжает в `archive/<номер>_<код>/`
  с `info.txt`: номер, код, дата, услуга, кто и когда удалил, список файлов. Контактов нет.

Архив проверяется на персональные данные и чистится вручную. Удаление мимо панели (окончательное удаление
из корзины в админке WordPress) **уводит файлы в архив** — так проектные данные не теряются случайно.

- **Клиент**: менеджер правит почту, телефон, имя и компанию; исправленное поле — медным, под ним серым

  Проверка ввода — в браузере (`type=email`, `pattern` у телефона) и на сервере (`normalize.php`): почта обязательна
  и приводится к нижнему регистру, российский телефон — к виду `+7 912 345-67-89`, иностранный — `+<цифры>`.

  «Клиент выбрал …» и «Сохранить»; REST `requests/<id>/work`.
- **Описание задачи** и **данные калькулятора** — сворачиваемые блоки: длинные (больше 600 знаков / 8 строк)
  свёрнуты по умолчанию. У старых заявок (до 0.8.1 форма дописывала расчёт текстом) всё после метки
  «— Данные из онлайн-калькулятора —» свёрнуто под строкой «Текст расчёта, приложенный клиентом». История и «Служебное» — тоже сворачиваются.
- **Данные калькулятора** — с названиями со страницы калькулятора (`calc-labels.php`): подписи полей, варианты
  списков, режим монтажа, строки и столбцы таблицы «Группа корпусов». Страница находится по разметке
  (`data-key="qty"` и `name="asm"`), разбор кешируется до её следующего сохранения; если страницы нет — запасные
  подписи в коде. Новые ключи калькулятора, которых плагин не знает, выводятся как есть.
- **Файлы**: менеджер добавляет файлы (например, досланные клиентом на почту) — те же проверки, что у формы.
  У файла видно, кто и когда его добавил; вложения писем помечены «отправлено клиенту».
- **Заметки**: удалить заметку может её автор или администратор (`pcb_crm_note_delete()`, REST `requests/<id>/note-delete`):
  текст удаляется насовсем, в истории остаётся «Удалена заметка от <дата>, автор — <имя>».
- **Заметки**: галочка «Важно». Важные заметки закреплены над остальными и подсвечены, пока отметку не снимут;
  снятие — в истории. Блок сворачивается; если внутри есть открытые важные — у блока медная рамка (видна и в свёрнутом),
  в заголовке «важных: N». В списке заявок у номера — значок «!».
- **Заметки и история** — с прокруткой: блок до 380 px (≈ 6 записей истории или 4–5 заметок). Низ затеняется,

- **Связанные заявки** — блок есть всегда: заявки того же контакта и компании (§6.1), затем совпадения по почте,
  телефону или компании (ключи `_pcb_k_*`); у каждой — по какому признаку; если таких нет — так и написано.
- **Имена пользователей** везде — отображаемое имя, при наведении — логин (`pcb_crm_user_html()`). В журнале хранится
  ID пользователя, поэтому смена имени не теряет авторство.
- **Письмо клиенту** — кнопка «Ответить» открывает отдельное окно: тема «Заявка № <код> — PCB Восток»,

  From и Reply-To — общий ящик `PCB_MAIL_FROM`, скрытая копия — туда же (SMTP не кладёт письмо в «Отправленные»).
  Отправленные письма — в разделе «Переписка». Ответы клиента приходят в почту, в CRM не попадают.
- **«Показать в калькуляторе»** (0.7.1) — в заголовке блока «Данные калькулятора», если в заявке есть расчёт
  (`_pcb_calc`). Открывает калькулятор в новой вкладке с параметрами и файлами из заявки:

  заявки и прежней оценкой — под полосой «Онлайн-калькулятор», в потоке страницы. Файлы — те, что клиент загружал в калькулятор (по именам из `calc.files`); файлы менеджера
  не берутся. Изменения в калькуляторе в заявку не сохраняются; посетители этого не видят — аналитика у вошедших
  не собирается.
- **Меню пользователя** в шапке — иконка, имя и стрелка: логин, «Мой профиль», «Пароль и двухфакторный вход»
  (профиль WordPress), «Выйти».
- **Мой профиль** `/panel/profile/`: отображаемое имя (меняет `display_name`, логин остаётся; смена — в журнале)
  и подпись в письмах (`user_meta pcb_mail_signature`; по умолчанию «С уважением, <имя>, PCB Восток, <сайт>»).
- **Только администратор**: выгрузка CSV (`;`, UTF-8 с BOM, значения из формы защищены от формул Excel),

### 6.1 База клиентов ✅ (0.6.0)

Две сущности, как в amoCRM / Битрикс24: **компания** (реквизиты) и **контактное лицо** (человек; компания — у контакта).
Заявка ссылается на контакт и компанию; её собственные данные (исходные и исправленные) остаются как есть.

Таблицы: `{prefix}pcb_companies`, `{prefix}pcb_contacts`, `{prefix}pcb_client_ids` (идентификаторы в едином виде:
`email`, `phone` — цифры, `domain`, `inn` → контакт или компания), `{prefix}pcb_match_skip` (отклонённые предложения).
Объединённая запись не удаляется — `merged_into` ведёт на ту, куда влита; старые ссылки открывают актуальную.

**Сопоставление новой заявки** (`match.php`; при обновлении до 0.6.0 — все старые, от ранних к поздним):

| Уровень | Признак | Что делаем |
|---|---|---|
| Точное | почта; мобильный телефон `+7 9…` | Заявка — к найденному контакту и его компании; новая почта/телефон добавляются контакту |
| Вероятное | корпоративный домен почты; название компании без формы собственности; одинаковое ФИО (порядок слов, регистр, ё/е не важны); общий **городской** номер | Новый контакт без компании, предложение — в очереди «Проверить» |
| Нет совпадений | — | Новый контакт; если в заявке указана компания — новая компания |

Городской номер не связывает сам: это часто общий телефон приёмной или отдела. Публичные домены (gmail, mail.ru,
yandex.ru и др., `pcb_cl_public_domains()`) компанию не определяют. Компания получает корпоративный домен,
когда к ней привязан контакт с такой почтой.

**Очередь «Проверить»** (`/panel/crm/clients/queue/`, число — на вкладке) вычисляется из данных: «контакт из этой
компании?» (`link`), «одна компания?» (`cmerge`), «один человек?» (`pmerge`). «Привязать» / «Объединить» — в более
раннюю запись (её значения главнее, пустые дополняются), «Это разные» — запоминается навсегда.

**Реквизиты компании**: наименования, форма собственности, ИНН, КПП, ОГРН/ОГРНИП, адреса (юридический, фактический,
почтовый; кнопка «как юридический»), банк, БИК, р/с, к/с, руководитель, должность, основание полномочий, телефон,
сайт, комментарий, «реквизиты проверены». Проверка: ИНН (10/12, контрольные числа), КПП (формат, у ИП — пусто),
ОГРН/ОГРНИП (13/15, контрольная цифра, соответствие типу ИНН), БИК (9 цифр, 04…), р/с и к/с — ключ по БИК.
ИНН уникален: вторая компания с тем же ИНН не создаётся — предлагается открыть существующую.

**Автозаполнение по ИНН** — DaData, только организации (ИНН из 10 цифр): ИНН ИП — персональные данные, в DaData
не уходит. Ключ — `PCB_DADATA_TOKEN` в `wp-config.php`; без ключа кнопки нет. Заполняются наименования, ОПФ, КПП,
ОГРН, юридический адрес, руководитель; занятые поля — только после подтверждения; если организация ликвидирована
или в процессе — предупреждение. Банковские реквизиты — вручную. Ответ кешируется на сутки.
Разбор ответа `findById/party` проверен на рабочем ключе (16.10.2026).

**Вручную, без заявки** (например, клиент позвонил): «Новая компания» и «Новый контакт» на странице «Клиенты»,
«+ Добавить контактное лицо» в карточке компании (компания подставлена). У контакта обязательны ФИО и почта или
телефон; почта или мобильный, уже принадлежащие другому контакту, дубль не создают — предлагается открыть
существующий. В истории — «Создан вручную» / «Создан из заявки». Будущие заявки с этой почты или мобильного
привязываются к нему сами.

**Карточка контакта**: ФИО, должность, компания (поиск по названию/ИНН; пусто — отвязать; заявки переходят вместе
с контактом), все почты и телефоны (добавить/убрать), заявки, объединение, история.
**Карточка заявки**: строка «Контакт · компания» со ссылками и «изменить привязку» (`requests/<id>/client`);
«Связанные заявки» — сначала заявки того же контакта и компании, затем совпадения по полям.
Все правки клиентов — в общем журнале (колонка `entity` = `company:<id>` / `contact:<id>`), «было → стало».

## 7. Аналитика ✅

### 7.1 Связь заявки с Яндекс Метрикой ✅

- Только если посетитель согласился на аналитические cookie (`PCBConsent.get() === 'all'`), иначе Метрика
  не загружается и связи нет.
- При отправке формы `request-form.js` берёт `ym(<счётчик>, 'getClientID')` (ждёт до 0,8 с) и шлёт
  `ym_client_id`; обработчик сохраняет его в `_pcb_ym_client`.
- После успешной отправки — `ym(<счётчик>, 'userParams', { pcb_request: <код> })`: в Метрике визиты ищутся
  по коду заявки. Контакты в Яндекс не передаются — только случайный код.
- В карточке — блок «Яндекс Метрика»: ClientID и код (копируются по клику), ссылки на отчёты «Посетители»,
  «Вебвизор», «Параметры посетителей». ❓ Ссылки ведут на отчёты целиком — отбор по ClientID делается сегментом
  в Метрике; прямую ссылку с фильтром проверить на рабочем счётчике.
- Ограничения: ClientID привязан к браузеру (разные устройства — разные истории). Собственная аналитика
  панели (§7, таблица событий) остаётся обезличенной и с заявками не связывается — намеренно.

- Собственные события: таблица `{prefix}pcb_events` (день + событие + значение + количество), без IP,
  cookie и идентификаторов. Белый список событий — `pcb_events_whitelist()`. Браузер шлёт на
  `POST pcb-panel/v1/e`, сервер — `do_action( 'pcb_event', $event, $value )`. Хранится 2 года, чистка ежедневно.
- Яндекс.Метрика и Вебмастер — через API (`yandex.php`), данные кешируются; Метрика на сайте грузится
  только после согласия на cookie.
- Периоды: 7, 30, 90, 180 дней и год (`?days=7|30|90|180|365`), сравнение — с предыдущим периодом той же длины.
  Ограничений по данным нет: заявки — все, свои события хранятся 2 года (`PCB_EVENTS_KEEP_DAYS`, ровно хватает на год
  и сравнение с прошлым годом), Метрика и Вебмастер отдают историю с момента подключения сайта.
- Верх страницы — две строки: период · свежесть данных с троббером · «Обновить»; ниже — переходы по разделам.
- Пока данные грузятся (первая загрузка, смена периода, «Обновить») — троббер у надписи «Загружаем данные…»,
  блоки полупрозрачны.
- Подробности модуля дописывает чат аналитики.

## 8. SEO и техработы ✅ (этап 1, плагин 0.7.0)

Своя реализация вместо SEO-плагина: страниц мало, а нужен контроль над тем, что уходит поисковикам.
Вкладка `/panel/seo/`: **Страницы** · **Данные сайта** · **robots.txt** · **Техработы**. Сверху на каждом экране —
строка состояния: домен, индексация, техработы, конфликты.

### 8.1 Боевой и тестовый домен ✅

- Боевой домен — константа `PCB_SEO_PROD_HOST` (по умолчанию `pcb-vostok.ru`, `www.` не учитывается).
- На любом другом адресе (сейчас `pcbvostok.tw1.ru`) сайт закрыт от поиска тремя способами сразу:
  robots.txt `Disallow: /`, `<meta name="robots" content="noindex, nofollow">` (фильтр `wp_robots`)
  и заголовок `X-Robots-Tag: noindex, nofollow`. Работает всегда, даже при включённом стороннем SEO-плагине.
- После переезда на боевой домен ничего переключать не нужно. Галочка WordPress «Попросить поисковые
  системы не индексировать сайт» по-прежнему действует и показывается в строке состояния.

### 8.2 Мета страниц ✅

Метаполя страницы: `_pcb_seo_title`, `_pcb_seo_description`, `_pcb_seo_og` (id картинки, 0 — общая),
`_pcb_seo_noindex` (`'1'`). Управляются опубликованные страницы (`pcb_seo_pages()`, главная первой).

- **Title.** Пусто — по шаблону: главная — бренд, остальные — «Страница — бренд» (`pre_get_document_title`).
- **Название страницы** (`post_title`) правится здесь же; адрес (slug) не меняется. Используется в панели, в списке
  страниц WordPress и в title по шаблону; на самой странице заголовок задаётся блоками, не им.
- **Description.** Пусто — тег не выводится (вырезанный кусок текста хуже, чем сниппет, собранный поисковиком).
- **Open Graph и Twitter:** type, locale `ru_RU`, site_name, title, description, url, image 1200×630, alt;
  `twitter:card = summary_large_image`. Картинка — своя у страницы или общая из «Данных сайта»,
  иначе `assets/seo/og-default.jpg`. SVG не годится: мессенджеры его не показывают — загрузка принимает JPG/PNG/WebP до 5 МБ.
- **canonical** выводит сам WordPress (`rel_canonical`) — не дублируем.
- **«Не индексировать»** → `noindex, follow` и исключение из карты сайта. Главную закрыть нельзя (для этого — техработы).
- Ориентиры длины (`PCB_SEO_LEN`): title 15–60 знаков (>70 — «обрежет»), description 120–160 (>200 — «обрежет»).
- Экран правки: счётчики, превью сниппета (по мотивам выдачи Яндекса) и карточки ссылки в мессенджере — на лету.
- Сохранение меняет только присланные поля; после него сбрасывается кэш страницы (WP Super Cache).

### 8.3 Данные сайта и разметка ✅

Опция `pcb_seo`: бренд, юрлицо, телефон, почта, индекс, город, адрес, логотип, общая картинка, свои строки robots.txt.
Значения по умолчанию — из `docs/facts.md`: F-1.10 (бренд, ООО «ВТК ВОСТОК»), F-1.25 (адрес офиса),
F-1.26 (телефон), почта — как на сайте.

- На главной — JSON-LD `@graph`: `Organization` (name, legalName, url, logo, email, telephone, PostalAddress)
  и `WebSite` (publisher → организация).
- ИНН, ОГРН и другие реквизиты в разметку **не попадают** — по F-1.10 они публикуются только в политике ПДн.
  Часы работы не указываем.
- Логотип по умолчанию — из темы: `assets/icons/logo/logo.png` (светлый знак на тёмно-зелёном, как в шапке);
  на заглушке техработ — векторный `logo-light.svg`. Нет файла в теме — логотип в разметку не выводится.
- Телефон проверяется и приводится к виду `+7 917 510-09-68`, в разметке — `+79175100968`.

### 8.4 robots.txt и карта сайта ✅

- robots.txt собирает фильтр `robots_txt` (`pcb_seo_robots_txt()`): закрыты `/panel/`, `/wp-admin/`
  (кроме `admin-ajax.php`), `/wp-json/`, `/wp-login.php`, поиск, ссылки предпросмотра; `Clean-param` для
  utm-меток, yclid, gclid, ysclid (Яндекс склеивает адреса с метками; директива межсекционная, Google её пропускает);
  строка `Sitemap`. На экране — подробная справка по каждому правилу, разница `Disallow` и «Не индексировать»,
  где проверить файл в Вебмастере и Search Console. Свои строки — в конце, проверяются (только известные директивы, `Disallow: /` запрещён).
- Если в корне сайта лежит физический `robots.txt`, сервер отдаёт его — панель об этом предупреждает.
- Карта сайта — штатная `wp-sitemap.xml`: убраны авторы и рубрики/метки, оставлены страницы и записи,
  страницы с «не индексировать» исключены. `/panel` и заявки (`pcb_request` не публичный тип) в карту не попадают.

### 8.5 Сторонние SEO-плагины ✅

Если включён Yoast, Rank Math, All in One SEO или SEOPress (`pcb_seo_conflict()`), наш вывод мета, разметки,
robots.txt и фильтры карты сайта выключаются, вкладка показывает предупреждение. Защита тестового домена остаётся.

### 8.6 Режим техработ ✅

Заменяет плагин Under Construction & Maintenance Mode (его нужно отключить и удалить — §11).

- Опция `pcb_maintenance`: включён ли, заголовок, текст, ключ предпросмотра, когда и кем переключён.
- Включён → посетитель получает заглушку (`templates/maintenance.php`) с кодом **503** и `Retry-After: 3600`:
  поисковики считают сайт временно недоступным и не выкидывают страницы из индекса. На заглушке — заголовок,
  текст и контакты из «Данных сайта».
- Сайт как обычно видят: вошедшие пользователи панели (администратор и менеджер) и открывшие **ссылку
  предпросмотра** `/?pcb_preview=<ключ>` (cookie на 7 дней; «Выпустить новую ссылку» отключает старые).
- **Подпись под текстом** (`sign`) — свои строки; почта и телефон становятся ссылками, остальное — текст. Пока не
  задана — почта и телефон из «Данных сайта» (`pcb_maint_sign()`). Превью заглушки — внизу экрана на всю ширину.
- Не перехватываются: `/panel`, вход и консоль WordPress, REST (форма заявки), robots.txt, карта сайта.
- Пока режим включён, страницы не кэшируются (`DONOTCACHEPAGE`); при переключении кэш сбрасывается.
  Иначе страница, открытая по ссылке предпросмотра, попала бы в кэш и ушла посетителям.
- **Переход с плагина:** при первом запуске 0.7.0, если Under Construction ещё включён, режим техработ включается
  сам (однократно, `pcb_maint_migrated`) — после отключения плагина сайт не откроется раньше времени.
- Администратору в чёрной панели WordPress на сайте — медная метка «Техработы: сайт закрыт для посетителей».

### 8.7 Журнал ✅

Изменения пишутся в общий журнал (`entity` = `seo:<id страницы>`, `seo:site`, `seo:robots`, `seo:maint`)
в виде «было → стало»; история показывается на каждом экране вкладки, в «Журнале» CRM — со ссылкой на экран.

### 8.8 Значок сайта (favicon) ✅

- Задаётся **темой**, а не «Иконкой сайта» WordPress: так работают SVG и полный набор размеров. Рисунок — вариант V4
  «Круглая плашка» — чип на круге основного зелёного `#14543E` (артефакт «Значок PCB Восток»); 16/32/48 px — проверенные пиксельные рендеры оттуда.
- Тема (`inc/favicon.php`) выводит в `<head>` сайта и страницы входа: ICO, SVG, PNG 96 (Google), PNG 120 (Яндекс),
  apple-touch-icon 180 (без прозрачности), манифест (192, 512, maskable 512), `theme-color #0B2C22`;
  стандартный `wp_site_icon` отключён. Прямой запрос `/favicon.ico` отдаёт файл темы (хук `do_faviconico`).
- Панель и заглушка техработ не вызывают `wp_head()` — подключают те же ссылки через `pcb_seo_icon_links()`.
- «Данные сайта» показывают значок (вкладка в светлой и тёмной теме, iPhone) — только просмотр; меняется через репозиторий.
  Превью сниппета на экране страницы — с этим значком.

## 9. Калькулятор ✅ (плагин 0.8.0; форма заявки — 0.8.1, несколько плат — 0.8.2, лимиты файлов — 0.8.3)

Сайтовая часть (разбор файлов, платы и комплект, данные заявки) — `wp-content/themes/pcb-vostok/docs/calculator.md`.

Вкладка `/panel/calc/`: менеджер видит, из чего складывается цена на сайте, правит ставки и публикует их сам.
Считает **только сервер** — `includes/calc/engine.php`, одна функция `pcb_calc_run()` и для сайта, и для панели,
поэтому цифры в панели и на сайте не расходятся. Значения по умолчанию — демонстрационные.

### 9.1 Цепочка расчёта

Восемь шагов (порядок = порядок вычисления): **Фабрика · Платы** (¥) → **Фабрика · Монтаж** (¥) → **Курс и платёж** →
**Доставка** → **Таможня** → **Наши услуги** → **Наценка** → **НДС и вид цены**; отдельно — **Инженер и сроки**
(когда сайт не считает сам: материал, слойность, импеданс, тонкая дорожка и т. п., и какой срок показывать).

- Платы: подготовка (+ за каждый слой сверх двух) + площадь партии × ставка за дм² по слойности × множители
  (толщина, медь, покрытие, материал, маска, две стороны, объём партии).
- Монтаж: (запуск + трафарет) × сторон + позиций × катушка + паек на плату × цена пайки × тираж + рентген для BGA/QFN.
- Курс: ЦБ × (1 + надбавка банка) × (1 + комиссия за платёж) × (1 + запас на курс). Разница с ЦБ — строка «Оплата фабрике».
- Доставка: вес (площадь × толщина × плотность + упаковка) × тариф выбранного способа, не меньше минимума за отправку.
- Таможня: пошлина от таможенной стоимости (платы + монтаж + доставка) + сбор + брокер; НДС на ввоз — к вычету
  (галочка) или в себестоимость.
- Наценка — отдельно на платы (вместе с доставкой, таможней и нашими услугами) и на монтаж.
- НДС 22 % (с 01.01.2026), минимальная сумма заказа, округление, вилка «от–до» (−10 / +15 %).

**Формула цены на экране — она же навигация по шагам:** общая строка `Платы + Монтаж + Оплата фабрике + Доставка +
Таможня + Наши услуги + Наценка + НДС = Стоимость`. У каждого слагаемого — номер и название шага, название словами,
под ним мельче — сумма; нажатие открывает редактор шага, точка — в шаге есть изменения черновика. Ниже — разбор каждого
блока тем же способом: параметр словами, под ним значение (сумма, число, множитель ×1,25 или процент).
Множители, равные 1, не показываются. Пример — для выбранного эталонного заказа; если он не считается — слагаемые
с прочерками, но шаги всё равно открываются. Отдельной «цепочки» нет — она дублировала формулу.

### 9.2 Валюты

Каждый денежный параметр хранится в своей исходной валюте (`cur` в модели): прайс фабрики — в юанях, доставка,
таможня, наши услуги и минимальная сумма — в рублях. **Валюта отображения** (₽ по умолчанию / $ / ¥, запоминается в
браузере) — только показ: все суммы и поля пересчитываются по курсу ЦБ, который виден под переключателем. Число,
введённое в любой валюте, пересчитывается обратно в исходную. В цену для клиента идёт курс с надбавками (шаг 3).
**На сайте — всегда рубли.**

Курсы ЦБ (`cbr.ru/scripts/XML_daily.asp`, юань и доллар) загружаются дважды в сутки (WP-Cron `pcb_calc_rates`) и по
кнопке «Обновить»; хранятся с историей за 30 загрузок (график). Галочка «Закрепить курсы вручную» — расчёт по
введённым курсам. Пока ЦБ не загружен — тоже по ручным.

### 9.3 Черновик, публикация, версии

- Каждая правка сохраняется в общий черновик (`pcb_calc_draft`, номер ревизии против одновременной правки двумя
  сотрудниками) и сразу пересчитывает эталоны: цена на сайте сейчас и по черновику, разница больше 15 % — красным.
- «Опубликовать…» показывает список изменений и разброс по эталонам, просит комментарий. Значения вне допустимого
  не публикуются. Версии — `pcb_calc_versions` (последние 60), в журнал — `calc_publish`.
- «Версии»: кто, когда, что изменено, как сдвинулись эталоны; любую старую версию можно взять в черновик.
- Эталоны: 5 типовых заказов + до 12 из заявок («+ эталон» по номеру заявки, берутся данные калькулятора).
- «Что сильнее всего влияет на цену» — насколько вырастет цена эталона, если параметр вырастет на 10 %.

### 9.4 Сайт

- **До первой публикации** сайт считает по старой формуле темы в браузере. После неё плагин передаёт калькулятору
  `window.PCBCalcServer`, и тот отправляет на `POST pcb-panel/v1/calc/quote` **только значения полей**
  (слойность, размеры, тираж, материал, покрытие, монтаж). Файлы проекта и их содержимое не отправляются. Сервер
  ничего не сохраняет; ограничение — 600 расчётов за 10 минут с адреса (хранится хеш, не адрес).
- Ответ — вилка, цена за плату, строки «из чего складывается» (наценка и расходы на платёж разнесены по строкам),
  «в т. ч. НДС 22 %», срок. Разбор для панели на сайт не уходит.
- Заявка запоминает номер версии формулы (`calc_version` в `_pcb_calc`) — в карточке строка «Версия формулы».
- FAQ страницы калькулятора: «Куда попадают файлы и параметры» — файлы никуда, параметры — на сервер.

## 11. Деплой

- Плагин лежит в репозитории рядом с темой и доставляется на сайт тем же путём (Gitium); после первого
  появления — активировать в «Плагинах».
- Изменились права или структура данных — поднять `PCB_PANEL_VERSION`: роли и миграции применятся сами.
- Таблицы создаются через `dbDelta` по своей версии (`pcb_events_db_version`, `pcb_request_log_db_version`),
  данные заявок обновляются по `pcb_rq_data_version`, правила адресов пересобираются при смене версии плагина.
- **Плагин должен быть активен**: форма заявки отправляет данные на его адрес `pcb/v1/request`; если плагин
  выключен, форма покажет ошибку отправки.
- `wp-content/updraft/` и `wp-content/uploads/` не попадают в git (`.gitignore`).
- Проверено на чистом WordPress + SQLite: приём, отказ для исполняемых файлов и пустых заявок, хранение вне
  веб-корня, права менеджера и администратора, правки и nonce, удаление в архив/безвозвратно/из корзины,
  выгрузка CSV, миграция старых заявок; в 0.4.0 — подписи калькулятора по настоящей странице, правка контактов,
  загрузка файлов, важные заметки, письмо с подписью и вложениями (перехват почты), стирание текстов при удалении;
  в 0.6.0 — разбор старых заявок по клиентам, очередь (все три типа), объединение, контрольные суммы на реквизитах
  ПАО Сбербанк, автозаполнение (подменный ответ DaData), городской и мобильный телефон; в 0.7.0 — тестовый и
  «боевой» домен (robots.txt, noindex, X-Robots-Tag, карта сайта), мета и Open Graph, разметка, права менеджера
  (только просмотр), загрузка картинок, конфликт с Yoast, техработы: 503 для посетителя, обход для панели, ссылка
  предпросмотра и её отзыв, переход с плагина Under Construction; в 0.8.0 — калькулятор: черновик и ревизии, публикация
  и откат версий, эталоны из заявки, переключение валюты, сайт до и после первой публикации, расчёт инженером,
  в запросе с сайта — только значения полей.
- **Калькулятор (0.8.0):** после обновления сайт продолжает считать по старой формуле. Внести реальные ставки во
  вкладке «Калькулятор», проверить эталоны и опубликовать первую версию — с этого момента сайт считает на сервере.
- **Переход на техработы панели (0.7.0):** после загрузки и обновления плагина режим техработ включится сам, если
  Under Construction был включён. Затем в «Плагинах» WordPress отключить и удалить Under Construction & Maintenance
  Mode — Gitium уберёт его папку из репозитория. Проверить в окне инкогнито, что видна заглушка панели.

## 12. Правила разработки

1. Права, а не роли; у каждого REST-эндпоинта свой `permission_callback`.
2. Скрытая кнопка — не защита: изменение проверяется на сервере.
3. Персональные данные не уходят третьим лицам и не пишутся в журналы и аналитику.
4. Хранение заявок — в плагине; тема отвечает только за вид формы.
5. Не дублировать данные: CRM читает те же записи `pcb_request`, что создаёт форма.
6. Изменил поведение — обнови этот файл в том же коммите.

## 14. Открытые вопросы ❓

- Реальные ставки калькулятора (фабрика, монтаж, доставка, таможня, наценка) — сейчас демонстрационные; до их
  внесения первую версию формулы не публиковать. Селектор способа доставки в калькуляторе сайта — не решено.
- Упоминать ли в политике ПДн, что капча передаёт данные Яндексу (из чата формы).
- **Расчёт комплекта на сервере** (до публикации формулы): `calc/quote` считает одну плату, калькулятор шлёт запрос
  на каждую и складывает ответы — доставка (минимум за отправку), таможня и брокер, `minOrder`, округление
  должны считаться один раз на заказ. Решить: аудит файлов и ПМИ — на плату или на заказ. Предложение API —
  `{ set: { sets, boards: [ { name, n, data } ] } }` → `{ ok, lo, hi, per, total, ship, saving, boards[] … }`,
  флаг для калькулятора `window.PCBCalcServer.set = true` (§3.9).
- Эталон из заявки с комплектом берёт только открытую плату — эталон-комплект или выбор платы (§3.9).
- Срок хранения заявок и файлов, автоочистка — не решено.
- «Удалить данные клиента» по запросу субъекта ПДн (обезличить все его заявки) — не реализовано.
- Политика ПДн: добавить, что к заявке привязывается идентификатор Яндекс Метрики (при согласии на аналитику)
  и код заявки передаётся в Метрику как параметр посетителя.
- Чтение ответов клиента из почтового ящика в CRM — не реализовано (нужен отдельный модуль IMAP).
- Заявка указывает другую компанию, чем у найденного по почте/телефону контакта, — сейчас побеждает компания контакта; при необходимости добавить такой случай в очередь.
- «Удалить данные клиента» теперь логично делать из карточки контакта (обезличить контакт и все его заявки) — не реализовано.
